# Web UI developer guide

The web UI (Phase 3.3, [spec](sharpclaw-3.3-implementation-spec.md)) is a React + TypeScript app in
[`ui/`](../ui), built with Vite and served by the gateway from its client listener (same origin, no
extra container). The gateway is still the only trust boundary: the UI holds no secrets and talks
only to `/api/*` on its own origin.

## Setup

Node 24 LTS (pinned in `ui/.nvmrc` and the Docker build stage), npm with the committed lockfile.

```bash
cd ui
nvm use            # Node 24
npm ci
npm run dev        # Vite on http://localhost:5173, proxying /api, /openapi, /healthz
```

The dev server needs a gateway on `http://localhost:8080` (override with `SHARPCLAW_GATEWAY`). The
easiest is the Compose stack with the dev override, which switches to the fake provider and allows
the Vite origin for cookie-authenticated requests:

```bash
cd docker
docker compose --env-file ../.env -f compose.yml -f compose.dev.yml up -d gateway
SHARPCLAW_URL=http://localhost:8080 sharpclaw users create kevin   # first user, once
```

`Auth__AllowedOrigins__0=http://localhost:5173` lives only in `compose.dev.yml`; never put it in
the base Compose file.

## Scripts

| Script | What it does |
|---|---|
| `dev` | Vite dev server with the API proxy |
| `build` | Type-check, production build into `ui/dist`, then `scripts/check-dist.mjs` (fails on inline script/style in `index.html`, warns above 250 KB gzipped initial JS) |
| `lint` | ESLint (typescript-eslint, react-hooks, jsx-a11y and the restricted-API rules below) |
| `typecheck` | `tsc --noEmit` (`strict` + `noUncheckedIndexedAccess`) |
| `test` | Vitest + React Testing Library + MSW + jest-axe (`tests/`) |
| `test:e2e` | Playwright (`e2e/`), see below |
| `gen:api` | Regenerates `src/api/schema.d.ts` from `docs/openapi/sharpclaw-client.v1.json` |
| `check:api` | Regenerates and fails if `schema.d.ts` changed (run in CI) |
| `format` | Prettier |

To run the gateway against a local build without Docker, point `Ui__RootPath` at `ui/dist`.

## The API contract

- `docs/openapi/sharpclaw-client.v1.json` is the committed contract, generated by the gateway
  (`GET /openapi/v1.json`, authenticated, client routes only). `SnapshotTests` fails when the
  document changes; refresh with
  `UPDATE_OPENAPI=1 dotnet test tests/SharpClaw.Gateway.Tests --filter FullyQualifiedName~SnapshotTests`,
  then `npm run gen:api`, and commit both.
- The typed client is `openapi-fetch` (`src/api/client.ts`). Always go through
  `call(() => api.GET(...))`: it throws `ApiError`, signs out on `401`, and on `403 csrf_failed`
  re-fetches the session and retries once.
- The CSRF token is held in memory only and sent as `X-CSRF-Token` on non-GET requests.
- Error codes and fail reasons map to plain text in `src/api/errors.ts` (one table, unit-tested).

## Live events

One `EventSource('/api/events')` per tab (`src/api/stream.ts`, `EventStreamManager`). Over plain
HTTP/1.1 a browser allows six connections per host and each tab's stream uses one, so about four
tabs is the practical limit.

- The browser's own reconnect handles drops and re-sends `Last-Event-ID`.
- If the `EventSource` ends `CLOSED` (a non-200 response), the manager checks
  `GET /api/auth/session`: signed out → back to login; otherwise a new `EventSource` at
  `/api/events?lastEventId=<last>` after 1 s, 2 s, 5 s, then 10 s.
- A tab hidden for more than 10 s is reopened when shown; so is every `online` event.
- Durable events are de-duplicated by id. `reset` invalidates everything; a `ready` after a
  reconnect refetches the thread list, open thread and approvals.
- `src/api/eventEffects.ts` maps each event to cache invalidation or the live store
  (`src/api/live.ts`, streamed text and running tools per correlation id, outside the query cache,
  rendered at most once per animation frame).

Payloads (sample of each in `docs/api-fixtures/events/`; types in `src/api/events.ts`, checked
against the fixtures by `tests/events.test.ts`). Every payload has `threadId` (null only on the
global stream's `ready`/`reset`).

| Event | Durable | Payload |
|---|---|---|
| `ready` | id = replay baseline | `threadId` |
| `reset` | no | `reason`, `threadId` |
| `thread.created` | yes | `threadId`, `agentId` |
| `thread.updated` | yes | `threadId`, `title`, `archived` |
| `message.created` | yes | `messageId`, `threadId`, `correlationId` |
| `delta` | no | `correlationId`, `content`, `threadId` |
| `snapshot` | no | `correlationId`, `content` (all text so far), `threadId` |
| `tool.requested` | yes | `correlationId`, `toolCallId`, `toolName`, `threadId` (never arguments) |
| `approval.requested` | yes | `approvalId`, `correlationId`, `toolName`, `summary`, `risk`, `reason`, `expiresAt`, `threadId` |
| `approval.decided` | yes | `approvalId`, `correlationId`, `status`, `decidedBy`, `threadId` |
| `message.completed` | yes | `correlationId`, `messageId`, `content`, `threadId` |
| `error` | yes | `correlationId`, `code` (the fail reason), `message` (readable text from `FailReasons.Describe`), `threadId` |

## Security constraints

**Content Security Policy.** HTML from the gateway carries
`default-src 'none'; script-src 'self'; style-src 'self'; img-src 'self' data:; font-src 'self';
connect-src 'self'; manifest-src 'self'; base-uri 'self'; form-action 'self'; frame-ancestors 'none'`.
No inline scripts or styles, and nothing from another origin (no web fonts, CDNs or analytics).
React's `style` prop is applied through the CSSOM, which the CSP allows; `style="…"` in markup and
`<style>` elements are not.

Radix's dialogs, menus and selects lock page scroll with `react-remove-scroll`, which injects a
`<style>` element. Rather than loosen the CSP, `vite.config.ts` aliases that package to
`src/lib/removeScroll.tsx`, which locks scroll via `document.body.style`. The Playwright suite
asserts no CSP violations, so `style-src-attr 'unsafe-inline'` was not needed.

**Rendering.** Assistant text is markdown (`react-markdown` + `remark-gfm`, `skipHtml`, no
`rehype-raw`). Links are limited to `http(s)`, `mailto` and `#anchors`, open in a new tab with
`rel="noopener noreferrer nofollow"`. Images are never loaded: a markdown image becomes a text link
(prompt-injected content can't exfiltrate data through an image URL). User text, tool arguments and
tool results are always plain text. Messages over 200,000 characters render as plain text first.

**No secure context.** Over `http://<lan-host>` the browser has no `navigator.clipboard`,
`crypto.randomUUID()`, service workers or notifications. Copy buttons use a selected textarea and
`document.execCommand('copy')`, and values are always shown selectable; client ids come from
`src/lib/ids.ts`. ESLint forbids `navigator.clipboard`, `crypto.randomUUID`, `sessionStorage`,
`localStorage` outside `src/lib/prefs.ts` (one non-sensitive preference) and
`dangerouslySetInnerHTML`; the unit tests run with the first two undefined.

**Tokens.** A new agent token is shown once in a dialog that needs an explicit "I've saved it";
it lives only in that dialog's state (mutations are removed from the cache when it closes).

## Tests

- `npm test`: unit and integration tests with MSW handlers (`tests/msw.ts`) and a fake
  `EventSource` (`tests/utils.tsx`). `renderApp(route)` renders the whole app signed in.
- `npm run test:e2e`: Playwright against an isolated stack started by `e2e/stack.sh` (gateway
  with the fake provider and `ui/dist`, the CLI-created user, one agent process; ports 18480/18481,
  state in `/tmp/sharpclaw-e2e`). Run `npm run build` first. Set `E2E_BASE_URL` (with
  `E2E_ADMIN_KEY`, `E2E_USER`, `E2E_PASSWORD`) to target a running Compose stack instead. Projects:
  Chromium, WebKit and a mobile viewport (`@core` tests). WebKit needs the host libraries from
  `sudo npx playwright install-deps webkit`.
